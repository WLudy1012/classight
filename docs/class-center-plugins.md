# 班级中心插件

`/center` 与 `/admin` 共用工作台框架，导航、账号入口和页面外边距由宿主提供。服务端通过 `plugin/` 中的 DLL 发现插件，前端读取 `/api/v1/plugins/catalog` 更新入口；加载、替换和删除插件都不需要重启 daemon。DLL 编写及部署见 [DLL 插件开发](dll-plugins.md)。

内置班会、人机验证、课程表和成员权限插件均为独立 DLL。首次运行时 daemon 将它们释放到同目录的 `plugin/`；升级 daemon 时同步更新未手动更改的内置 DLL，手动替换过的文件保留，也不会补回手动删除的插件。业务数据独立保存在数据库中，卸载插件不会删除数据。

## 页面接入

新 DLL 可以把 HTML、JS、CSS 嵌入程序集，通过 `Manifest.UiEntry` 提供页面，工作台会在隔离 iframe 中打开。插件页面通过宿主消息桥调用自己的 API，无需获得用户令牌。新增这类插件无需重新构建前端。

内置插件保留 React 页面适配器，放在 `web/src/features/class-center/plugins/`。适配器只在对应 DLL 出现在服务端目录且插件启用时显示。后续为同一 ID 的 DLL 提供 `UiEntry` 后，工作台优先使用 DLL 页面。

React 适配器通过 `registerClassCenterPlugin` 声明 ID、相对 `/center` 的入口路径、图标、文案和路由，可用 `lazy` 加载页面。需要限制整个入口时声明 `permission`，服务端接口仍须独立授权。`legacyPath` 可声明旧路由；重复 ID、入口或路由会在启动时报错。

默认插件属于班级应用，显示在工作台工具列表与侧栏中。账户相关能力声明 `category: 'account'`，入口会归入账户设置页签，不与课程表、班会等日常应用混排。个人资料位于 `/center/account`，账号安全位于 `/center/account/security`；账户插件仍使用自己声明的相对路由，例如成员权限插件的 `/center/identity`。

插件页面应输出 `.page` 等内容容器，使用统一标题和操作区域，不再包裹 `PageShell`、全局导航或 `main`。内容宽度和外边距由 `WorkspaceShell` 控制；移动端抽屉导航也由外层负责。插件自己的表格、工具栏和编辑表单仍需适配窄屏。

旧 `/console` 进入 `/center`；`/console/profile`、`/console/security` 分别转到新的资料和安全页面，并保留查询参数与片段。

班会插件位于 `meetings.plugin.ts`，包括班会场次、报名和课件。所有登录用户可浏览场次；报名和课件操作继续由 `speech.participate`、`speech.manage` 及服务端业务规则控制。班会管理员可以查看草稿、新建与编辑场次、开放报名，并在现场开始、完成、跳过或调整发言顺序。课件转换需要服务器可用的 LibreOffice。

## 插件管理

管理中心在 `/admin/plugins`，支持搜索、筛选和配置插件，并显示 DLL 文件、加载状态、版本、重载次数和失败提示。修改启用状态需要 `site.settings.write`。加载错误的完整原因在 daemon 日志中查看。

“加载”表示 DLL 已成为可用模块；“启用”是数据库中的业务开关。默认启用班会和课程表，默认停用人机验证和成员身份扩展。停用班会后入口和接口不可用，数据保留。停用成员身份扩展后，插件权限验证接口不可用，系统已有权限规则不受影响。

后端插件通过依赖注入注册 `IManagedPlugin`，声明唯一 ID、默认启用状态、依赖及启用前的配置检查；业务接口必须自行检查该插件状态。依赖未启用时不能启用插件，也不能停用仍被已启用插件依赖的插件。内置配置页面仍可在 `web/src/features/admin/plugin-config/` 下注册，其他 DLL 由管理中心读取清单展示。

人机验证先保存服务商配置再启用。密钥由服务端加密保存，读取配置时不会返回明文；启用后若 DLL 缺失，登录验证会拒绝请求，避免绕过验证。模拟 API 不连接真实验证服务，因此不允许启用人机验证。

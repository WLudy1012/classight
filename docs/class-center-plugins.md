# 班级中心插件

班级中心负责登录、插件入口、路由和可选权限过滤；功能由插件提供。插件随前端构建打包，不支持在运行时上传或加载第三方代码。服务端权限仍由各模块的接口执行，前端过滤不能替代接口授权。

在 `web/src/features/class-center/plugins/` 下新增 `*.plugin.ts`，调用 `registerClassCenterPlugin` 声明唯一的 ID、入口路径、排序、图标、中英文文案键及页面路由。路由使用相对 `/center` 的路径，页面可通过 `lazy` 按需加载；需要限制整个功能时声明 `permission`。插件可选提供 `DockEntry` 作为主页入口，首页按同一权限过滤。旧地址可在路由上声明 `legacyPath`，参数、查询字符串与片段会保留并跳转到新地址。重复 ID、入口或路由会在启动时报错。

班会插件位于 `meetings.plugin.ts`，包括班会场次、报名和课件。所有登录用户可浏览场次；报名和课件操作继续由 `speech.participate`、`speech.manage` 及服务端业务规则控制。后端由已有 `SpeechModule` 注册服务、接口与权限，接口路径不变。新增带服务端功能的插件时，应实现对应的后端模块并独立校验权限；前端插件发现不会自动安装后端模块。

## 插件管理

管理中心在 `/admin/plugins`，只有拥有 `site.settings.write` 的用户可以更改插件状态。状态保存在数据库，默认启用班会插件，默认停用人机验证和成员身份扩展。停用班会后，其入口、页面和接口均不可用，数据保留。停用成员身份扩展后，插件权限验证接口不可用，系统已有权限规则不受影响。

后端插件通过依赖注入注册 `IManagedPlugin`，声明唯一 ID、默认启用状态、依赖及启用前的配置检查；业务接口必须自行检查该插件状态。依赖未启用时不能启用插件，也不能停用仍被已启用插件依赖的插件。前端可在 `web/src/features/admin/plugin-config/` 下增加 `*.plugin.tsx`，注册管理中心名称、说明和可选配置组件。班级中心入口仍通过独立的 `*.plugin.ts` 注册；两端使用同一插件 ID。管理中心自动发现已注册的插件，未提供展示描述时显示插件 ID。

人机验证先保存服务商配置再启用。密钥由服务端加密保存，读取配置时不会返回明文。模拟 API 不连接真实验证服务，因此不允许启用人机验证。
